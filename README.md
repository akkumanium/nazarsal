# NazarSal · Astana

Веб-приложение для прогулок по Астане: GPT-6 Luna разбирает запрос, PostGIS извлекает реальные OSM-объекты, код проверяет расписания и бюджет, openrouteservice или Geoapify рассчитывает пешеходные пути. Карточка на карте показывает текущую погоду Open-Meteo для Астаны: температуру, ощущаемую температуру, состояние неба и ветер. Погода не передаётся ИИ и не влияет на подбор мест. Векторного поиска, MediaWiki и Wikidata нет.

Погодный API работает без ключа: `/api/weather` запрашивает фиксированную точку Астаны и кеширует ответ Open-Meteo на 15 минут. GPS пользователя не передаётся погодному сервису. Карточка обновляется раз в 15 минут; при ошибке доступна кнопка повтора. Бесплатный API Open-Meteo предназначен для некоммерческого использования: [условия](https://open-meteo.com/en/pricing).

## Запуск

Нужны Node.js 22+ и pnpm 10+. Рекомендуется Node.js 24.

```sh
pnpm install
```

В `.env.local` укажите `OPENAI_API_KEY` и ключ выбранного сервиса маршрутов. По умолчанию используется openrouteservice с `ORS_API_KEY`. Ключи остаются на сервере. В репозитории есть `.env.example` со всеми настройками.

Для перехода на Geoapify зарегистрируйте ключ в [Geoapify MyProjects](https://myprojects.geoapify.com/) и добавьте в `.env.local`:

```env
ROUTING_PROVIDER=geoapify
GEOAPIFY_API_KEY=ваш_ключ
```

Перезапустите dev-сервер. Для возврата к ORS задайте `ROUTING_PROVIDER=ors` и заполните `ORS_API_KEY`. Требуется только ключ выбранного провайдера; автоматического переключения при ошибках нет. `pnpm check:connections` проверяет матрицу и геометрию маршрута выбранного сервиса на двух точках Астаны.

Оба провайдера используются для пешеходных матриц и маршрутов с проверкой подхода к каждой остановке (до 120 м). Кеш матриц разделён по провайдерам; GPS и точки, выбранные на карте, не сохраняются. При выборе Geoapify карта показывает ссылку Powered by Geoapify.

Бесплатный тариф Geoapify предоставляет 3000 кредитов в день. Матрица 13 × 13 (старт + 12 кандидатов) стоит 130 кредитов; один поиск может использовать до двух матриц и шести запросов маршрутов. Это примерно 11–22 поиска в день при полном наборе кандидатов без попаданий в кеш. Актуальные условия: [тарифы](https://www.geoapify.com/pricing/), [расчёт кредитов матриц](https://apidocs.geoapify.com/docs/route-matrix/#pricing).

### Supabase / обычный PostgreSQL

Создайте PostgreSQL с PostGIS и pg_trgm. Для Supabase используйте Session pooler и серверный DATABASE_URL; пароль с особыми символами нужно URL-кодировать.

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/postgres
DATABASE_SSL=true
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-6-luna
ORS_API_KEY=...
```

```sh
pnpm db:migrate
pnpm check:connections
pnpm data:collect
pnpm data:audit
pnpm dev
```

Приложение: http://127.0.0.1:3000.

### Локальная база без Docker

Для разработки доступен настоящий встроенный PostgreSQL PGlite с экспериментальным расширением PostGIS. Это дополнительный локальный режим; production рассчитан на Supabase/PostgreSQL. В этой рабочей папке локальная база уже инициализирована.

```dotenv
# DATABASE_URL должен отсутствовать или быть пустым.
LOCAL_DATABASE_PATH=.local/postgres
OPENAI_MODEL=gpt-6-luna
OPENAI_API_KEY=...
ORS_API_KEY=...
```

Команды миграции и сбора те же. Сначала завершите сбор, затем запускайте веб-сервер: файловая база поддерживает один процесс, совместная работа CLI и веб-сервера не допускается. Локальный PostGIS запускается без оптимизирующего WASM-компилятора для стабильной работы V8 на Windows.

Без ключей и опубликованного датасета интерфейс открывается и показывает состояние подключений. Тестовые объекты не подставляются в рекомендации.

## Сбор всего города

`pnpm data:collect` создаёт или продолжает незавершённый импорт. `pnpm data:collect --new` начинает новую версию.

- Граница: OSM relation **3087156**, настраивается через `ASTANA_BOUNDARY_RELATION_ID`. Можно передать сохранённый полный Overpass JSON границы через `ASTANA_BOUNDARY_FILE`.
- Квадраты 5 × 5 км строятся в EPSG:32642; для API переводятся в WGS84. На ошибках запроса они делятся до трёх раз. Ошибки SQL и повреждённая геометрия останавливают импорт.
- Запросы включают node/way/relation и безымянные объекты. Используется единый каталог `src/lib/catalog.ts`, а не фиксированная выборка из центра.
- Все квадраты используют один `OSM_SNAPSHOT`. Исходные ответы хранятся в `data/raw/<run-id>/`; состояние — в `import_runs` и `import_tiles`.
- Публичный Overpass может возвращать 429/502/504. Загрузчик повторяет запросы и соблюдает Retry-After; можно изменить `OVERPASS_URL` на другой публичный или собственный экземпляр, поддерживающий исторические снимки. Не отключайте проверку TLS.
- Сетка покрытия 1 × 1 км хранит категории, неизвестные свойства, землепользование и расстояния до ближайших категорий. Пустые ячейки проверяются повторным POI-запросом.
- Новая версия публикуется транзакцией только после полной загрузки и проверки. До этого приложение использует предыдущую версию.
- Равное число POI в каждой ячейке не навязывается. Отчёт показывает реальное распределение выбранных объектов OSM; наличие всех реально существующих заведений OSM не гарантирует.

`pnpm data:audit` пишет `data/audit.json` и возвращает ненулевой exit code, если найдены незавершённые части или некорректные данные. Для проверки незавершённой версии: `pnpm data:audit --run=<uuid>`.

Не удаляйте файл `data/state/collect.lock` при работающем сборщике. Блокировка умершего процесса снимается автоматически при следующем запуске.

### Резерв: полный снимок OSM вместо публичного Overpass

Если публичные экземпляры Overpass недоступны, можно обработать полный `.osm.pbf` Казахстана от [Geofabrik](https://download.geofabrik.de/asia/kazakhstan.html). Это те же данные OpenStreetMap, без внешнего обогащения. Основная реализация остаётся на TypeScript; для чтения PBF используется отдельный необязательный Python-адаптер Pyosmium.

```sh
python -m venv .local/osm-tools
# Windows:
.local/osm-tools/Scripts/python.exe -m pip install -r scripts/osm-requirements.txt
# macOS/Linux: .local/osm-tools/bin/python -m pip install -r scripts/osm-requirements.txt

curl -fL -o data/raw/kazakhstan-latest.osm.pbf https://download.geofabrik.de/asia/kazakhstan-latest.osm.pbf
pnpm data:import-pbf
pnpm data:audit
```

Для другого расположения Python задайте OSM_PYTHON; для другого файла — `pnpm data:import-pbf --file=/absolute/path/snapshot.osm.pbf`. Сборщик сохраняет SHA-256 файла, время репликации из заголовка PBF и подготовленные геометрии. Повторный запуск переиспользует извлечение того же снимка и продолжает незавершённую версию. Ячейки без объектов проверяются по полностью прочитанному снимку повторным пространственным подсчётом; в их метаданных указан способ проверки. Источник покрывает весь город, плотность и количество объектов по районам не выравниваются.

Индекс координат PBF временно хранится в `.local`, а предварительные фильтры работают в нативном обработчике. Для полного снимка нужны дополнительное место на диске и несколько минут обработки; API-ключи для этого не нужны. После аварийного завершения могут остаться временные `*-nodes-*.idx`; удалять их можно только после остановки соответствующего импортера.

## Поиск и маршруты

### Проверенный исходный датасет

В этой рабочей папке опубликован снимок OSM от **2026-10-17 20:20:51 UTC**: **1436 доступных POI**, все 12 категорий, **55** квадратов загрузки и **932** ячейки проверки покрытия. У 287 исходных объектов указаны часы работы; 577 объектов без собственного имени сохранены с названиями категорий. Аудит: `data/audit.json`.

В 81 ячейке с жилым, деловым или торговым землепользованием выбранные POI отсутствуют в исходном OSM. Эти ячейки проверены и видны на карте: успешный импорт не означает, что там нет реальных заведений. Синтетические точки для заполнения пробелов не создаются.

1. Luna возвращает строгий `SearchIntent`. Категории и характеристики ограничены enum; SQL строится кодом с параметрами.
2. Старт: явный ориентир → выбранная точка → геолокация → уточнение. Названия ищутся по алиасам, полнотекстовому и trigram-поиску.
3. PostGIS применяет категории, исключения, обязательные характеристики и радиус. Рейтинг: 0.60 категории + 0.30 близость + 0.10 пожелания. До 60 кандидатов, с резервом мест для каждой цели; до 12 на маршрутизацию.
4. `opening_hours` проверяется на весь визит в `Asia/Almaty`. PH/SH без проверенного календаря и неразбираемые правила дают unknown. У парков без расписания нет автоматического статуса 24/7.
5. Планировщик перебирает до трёх остановок, учитывает направление переходов, обязательные цели и их порядок, время посещений, возврат и резерв. Невозможный музейный визит не сокращается до нескольких минут.
6. Directions повторно проверяет длительность, расписание и привязку каждой остановки. Обычный успешный запрос использует два вызова Luna, одну Matrix и одну Directions; альтернативы и отказы могут потребовать дополнительных Directions, максимум три проверки пути на запрос.
7. Модель пишет только объяснения и действия. Идентификаторы, названия, ссылки, времена и геометрия приходят с сервера. При отказе генерации используются шаблоны. При отказе маршрутов возвращаются места без вымышленных времён и линий.

Неизвестные данные не считаются отрицательными или подтверждёнными. Явное must-условие не снимается автоматически. `service:electricity=ask/limited`, цена, тишина и детские интерактивы не превращаются в безусловные обещания.

## API

| Метод | Назначение |
|---|---|
| `GET /api/places/search?q=...` | До 6 ориентиров из опубликованной базы |
| `POST /api/recommend` | Разбор запроса, поиск и проверка маршрута |
| `GET /api/coverage` | GeoJSON сетки покрытия |
| `GET /api/data-status` | Настроенные подключения и версия данных, без секретов |

Пример запроса:

```json
{
  "query": "Сначала кофе, потом парк. Есть 90 минут.",
  "origin": { "lat": 51.1282, "lon": 71.4304 },
  "controls": { "returnToStart": true },
  "excludedPoiIds": []
}
```

Для продолжения передавайте `previousIntent` из предыдущего ответа. Значения в `controls` явно переопределяют соответствующие параметры текста. `excludedPoiIds` позволяет заменить остановку. При неоднозначном ориентире ответ содержит `originChoices`; выбранные координаты передаются с `confirmedOriginQuery`.

Статусы: `ok`, `partial`, `needs_clarification`, `no_matches`, `service_unavailable`. Последний использует HTTP 503, ошибки формы — 400, ограничения частоты — 429. Лимит: 8 запросов/минуту на временный анонимный отпечаток, 500 в сутки на приложение по умолчанию. Это ограничение количества запросов, не гарантия фиксированного денежного расхода.

## Проверка

```sh
pnpm test
pnpm typecheck
pnpm build
```

Тесты используют синтетические fixtures только в `tests/`. Интеграционные проверки запускают настоящий PostgreSQL/PostGIS в памяти, выполняют миграцию, импорт, пространственный SQL, расписания, публикацию версии и отчёт покрытия. Другие проверки проверяют планировщик и отказы внешних сервисов. Они не подтверждают качество живой модели или доступ по вашим ключам — для этого выполните `pnpm check:connections` и реальные запросы после импорта.

## Размещение и данные

Для Vercel задайте DATABASE_URL, DATABASE_SSL, OPENAI_API_KEY, OPENAI_MODEL, ROUTING_PROVIDER и ключ выбранного провайдера (ORS_API_KEY или GEOAPIFY_API_KEY). Не используйте файловый LOCAL_DATABASE_PATH в serverless-среде. Импорт запускайте отдельно, с тем же DATABASE_URL, до демонстрации; в обработчиках веб-запросов Overpass не вызывается.

Точная геолокация не сохраняется в прикладных журналах и постоянных кешах. Матрицы сохраняются только когда старт — подтверждённый публичный POI. Данные маршрута с произвольным стартом остаются в рамках запроса. Сторонние провайдеры имеют свои политики обработки данных. OpenAI вызывается с `store:false`; это не обещание полного отсутствия служебного хранения.
